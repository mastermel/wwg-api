# 0005. Front-end stack: Mantine, TanStack Router/Query, installable PWA

- **Date:** 2026-09-27
- **Status:** Accepted

## Context

The design left the front-end stack open until step 9 (§6). The fixed
requirements: TypeScript throughout, a React SPA built and tested with Vite,
strict typing, a linter/formatter, an installable PWA, and some offline
viewing of cached data. Most users will be on desktop.

## Decision

- **Mantine** for components and styling (CSS Modules + CSS variables),
  with Tabler icons. Chosen over MUI (familiar, but heavier, with runtime
  CSS-in-JS), shadcn/ui + Tailwind (more assembly, more design ownership than
  needed) and React Aria (most styling work).
- **TanStack Router** (type-safe routes and search params) and **TanStack
  Query** (already generated by Orval), with the query cache **persisted to
  IndexedDB** for offline viewing.
- **React Hook Form + Zod**, with Zod schemas generated by Orval, so client
  validation mirrors the API's rules.
- **ESLint** (typescript-eslint `strictTypeChecked`) **+ Prettier**, chosen
  over Biome for its type-aware rules. TypeScript `strict`, without the
  extra strictness flags for now.
- **Vitest + React Testing Library + MSW** for tests.
- **PWA** with `vite-plugin-pwa`, **read-only offline** in v1.
- Look: mostly neutral, navy blue and silver, light/dark following the OS,
  desktop-first but responsive. Name **WWG Campaigner**.
- Each API step in Phases 2–3 ships with its screens.

## Consequences

- Full details in DESIGN.md §3.12; step 9 is split into four parts.
- To check during the scaffold: Orval with OpenAPI 3.1, and that Mantine's

- Offline edits, push notifications and end-to-end tests are deferred.
